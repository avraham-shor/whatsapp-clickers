## Successes

1. **Hands-on live-phone verification, every user-facing story.** Stories 2.1, 2.2, and 2.4 were each closed out with a real WhatsApp exchange on Avraham's phone (via cloudflared tunnel), not just scripted E2E — including catching that bidi-isolated example codes actually render left-to-right on a real device. Avraham named this the standout practice of the epic; it should continue exactly as-is.
2. **Compounding velocity from reused infrastructure.** Review-finding counts fell sharply as the epic progressed (12 → 12 → 10 → 5 across 2.3/2.3/2.4/2.5), and story 2.5 needed no new store queries, no new package, and no `main.go` change at all — pure consumption of surfaces 2.3/2.4 built generically. "Previous story intelligence" sections and per-story adversarial review continued from Epic 1 without interruption.
3. **Manual/real-environment testing caught what automated E2E structurally could not.** Story 2.3's React StrictMode double-socket bug (stuck on "מתחבר...") was found only in a real browser, not the Go E2E suite — a concrete argument for keeping manual verification in the loop even as automated coverage grows.
4. **Good judgment on a real spec conflict.** Story 2.5 explicitly diverged from epics.md's literal text ("any state past lobby → spectator") in favor of EXPERIENCE.md's authoritative conversation-grammar table, because sending a late-joiner the spectator promise ("results will arrive at game end") for an already-*finished* game would be a broken promise. Correctly treated as the single most important call in that story.
5. **Deliberate, well-reasoned degrade semantics.** Stories 2.3 and 2.4 handle a post-commit snapshot-build failure *differently* on purpose — 2.3 degrades to an empty snapshot (true in the moment), 2.4 skips the broadcast entirely (an empty snapshot there would be a false undercount). Reviewers pressed on this distinction each time and it held up.
6. **Meta setup, once complete, stayed solid.** No re-litigation of Meta pricing/throughput assumptions; the System User permanent token (rather than the 24h temporary one) removed an entire class of future friction.

## Challenges

1. **The Meta Business approval wait (~10 days) blocked story 2.1's completion.** Epic 1's retro action item promised a joint walkthrough "at Epic 2 kickoff, before development" — in practice, coding started the same day (2026-07-20) but Task 0 (Business Portfolio, verified test number, live E2E) wasn't done until 2026-07-30, an external approval-process dependency outside the team's control. Confirmed with Avraham: no comparable external dependency is expected for Epic 3 or beyond, so no process change is needed here.
2. **Story 2.1's review load was the heaviest of the project (~27 findings across two rounds).** Consistent with the Epic 1 retro's insight #1 ("infrastructure stories carry heavy hardening load") — 2.1 built the webhook/dispatch transport layer from scratch, the same shape as 1.1's walking skeleton.
3. **A concurrency-debt pile accumulated instead of being resolved.** Epic 1's retro action item 3 asked for a unified draft-only concurrency posture "inside story 2.3." Instead, each of 2.4 and 2.5 added its own TOCTOU race to the same family (join-state check-then-write, finished-game join, cross-game rename hijack, role-blind snapshot counts) and deferred it further — all explicitly chained to the same eventual fix point. Not a mistake (every one of these was correctly unreachable until a game could leave `lobby`), but the pile is now six deferred-work items deep and lands entirely on story 3.1.
4. **One review layer hit an operational spend/budget limit mid-review (story 2.4).** The Edge Case Hunter layer failed on a monthly limit and was only partially compensated by an inline pass — worth watching so it doesn't silently reduce coverage again on Epic 3's larger stories.

## Key Insights

1. Infrastructure-shaped stories (1.1, 2.1) reliably draw 2–4x the review load of feature stories built on top of established seams — budget for it rather than being surprised by it again in Epic 3's early infrastructure-shaped stories (3.1's state machine, 3.4's grading pipeline).
2. A TOCTOU race correctly deferred as "unreachable today" doesn't disappear — it compounds. When a deferred item's revisit trigger is a future story, that story's context should treat the *entire accumulated family*, not just its own new instance, as first-class scope.
3. Manual, human-in-the-loop verification (real phone, real browser) remains load-bearing even as the automated E2E suite matures — it caught a real bug (2.3) and validated a rendering property (bidi) that no scripted assertion could.
