## Successes

1. **Compounding review loop.** Each story's "Previous story intelligence" section carried forward the prior review's finding classes (body-size caps, boundary tests, differentiated error codes, handler-order precedence), driving patch findings down from 15 (story 1.1) to 2 (story 1.5). Story 1.5 wrote the review-mandated precedence tests in the TDD red phase before implementation.
2. **Zero undocumented architecture variances.** Every deviation from the canonical tree (`webdist/`, `cmd/provision/`, `dashboard-layout.tsx`, migration numbering offset, `package_id` FK naming) was recorded with rationale in the story file.
3. **Discovered constraints became written law.** The sqlc all-NOT-NULL/pgtype-free constraint surfaced in 1.2 and shaped the schemas of 1.3–1.5 with no regressions.
4. **UX and Hebrew discipline held from day one.** No Hebrew literals in components (all via `strings.he.ts`), filter-safety CI grep caught real fontsource injections from shadcn twice, visual E2E (headless Edge screenshots) verified RTL, 240px sidebar, bidi-isolated JOIN Codes, A8 time-limit guidance.
5. **Verification depth.** Every story shipped API-level E2E against real Postgres plus (from 1.3) visual browser E2E, with zero ERROR log lines as an enforced NFR-8 check.
6. **Meta pricing verification came back stronger than assumed** — service-window replies are both free and exempt from tier messaging limits (verified 2026-07 against official docs).
7. **Operator experience.** The Project Lead's verdict: the balance of autonomy vs. operator involvement (runbook-only human steps) was "exactly right."

## Challenges

1. **Windows environment friction (recurring, all stories).** Filtered network blocked Go toolchain download (manual SDK install with SHA-256 verification); `gh` CLI absent; `make` not stock; case-insensitive FS made the `App.tsx → app.tsx` rename invisible to git (Linux CI breaker, fixed by explicit staged rename); Hebrew mojibake through Git Bash `curl -d`; PowerShell UTF-16 default; transient `VirtualAlloc errno=1455` toolchain crashes; console cp1255 encoding crashed a Python script during this very retrospective. Managed — never blocked a story — because each trap was documented immediately (README Windows notes + story Dev Notes).
2. **First deploy failed twice (1.1).** Railway Nixpacks resolved stale toolchains (Go 1.22 / Node 18) → replaced with an explicit multi-stage Dockerfile; second failure was missing env vars (fail-fast working as designed). Lesson: prefer explicit Dockerfiles over platform auto-builders.
3. **Infrastructure stories carry heavy hardening load.** Story 1.1's review alone produced 15 patch findings (graceful shutdown, server timeouts, goose session lock, SPA asset 404, CI gate hardening). A walking skeleton is not a "light" story.
4. **Toolchain template churn.** Vite 8 shipped oxlint instead of ESLint; TS 6 deprecated `baseUrl`; shadcn CLI changed flags and injected an external font package twice. Mitigated by per-story web research before implementation.

## Key Insights

1. Infrastructure stories deserve a larger review budget than feature stories — plan for this again at 2.1 (webhook + dispatcher) and 2.3 (WebSocket hub), both infrastructure-shaped.
2. A constraint discovered once must become a written rule the next story inherits — the mechanism that made this work is the story files' "Previous story intelligence" section; preserve it.
3. Environment traps (encoding, FS case, filtered network) are a permanent tax on this machine; the cost is near-zero when each trap is documented at first encounter.
