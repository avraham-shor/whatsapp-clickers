# Spine Pair Review — whatsapp-clickers

Reviewed: `DESIGN.md` + `EXPERIENCE.md` (rev. 2026-07-09, OQ-7 revision) against PRD 2026-07-08 (UJ-1–UJ-5, FR-1–18), `epics.md` (UX-DR1–16), `architecture.md` (copy centralization, one-component-per-stage), `.decision-log.md` (A1–A14 user-confirmed), and the design-md-spec + three calibration example pairs. Reviewer: Finalize gate, rubric walk (Pass 1 mechanical, Pass 2 judgment).

## Overall verdict

A strong, source-extractable spine pair: all five PRD journeys are re-narrated as Key Flows with climaxes, every `{token}` reference in both files resolves, the conversation grammar (state × message-class) is genuinely contract-grade, and the two-palette / gold-discipline system is coherent end to end. One high-severity gap blocks clean downstream extraction — the Audience Display has no defined content for Free-Text Questions (question stage and reveal stage), which `epics.md` Stories 4.3/4.4 explicitly wait on. Beyond that, the issues are a cluster of copy-contract self-inconsistencies (emoji rule vs. templates, an unimplementable placeholder) and cross-document ripples (20s vs. 30s default, UX-DR15 supersession) that are cheap to fix but would confuse an AI story-dev if left standing.

UJ-N identifiers do match 1:1, so extraction is safe. *Fix:* soften the claim to "UJ numbers authoritative; titles rendered in Hebrew," or keep the PRD's English names in parentheses.
- **low** Flow 2 (UJ-2) has no failure path of its own; the wrong-answer and late-answer branches live in Flows 3 and 5 (EXPERIENCE.md Flow 2). Acceptable for the emotional-climax journey. *Fix:* optional one-line pointer to where its failure branches are narrated.

## 2. Token completeness — adequate

Extracted all frontmatter tokens (23 colors, 4 typography roles, 5 radii, 8 spacing steps, 13 components) and every `{path.to.token}` reference in the prose of both files. **All references resolve** — including all eight `{components.*}` references from EXPERIENCE.md into DESIGN.md's frontmatter. No missing hex on any plain color token. Verified the one stated contrast claim: white on `green-800` #166534 = 7.14:1 — correct.

### Findings
- **medium** Typography tokens use non-spec key names `family`/`weight` instead of the spec's `fontFamily`/`fontWeight` (DESIGN.md frontmatter `typography:`; design-md-spec.md "Frontmatter tokens" table). A spec-conformant token resolver will find empty typography objects. *Fix:* rename keys to `fontFamily`/`fontWeight`; keep `note`.
- **medium** `components:` frontmatter values are prose sentences with embedded `{refs}`, not token objects (DESIGN.md frontmatter vs. design-md-spec.md: "Component-name → object of component tokens"; compare `design-example-shadcn.md` `button-primary`). Content is complete and human/AI-readable, but the machine contract is degraded and the resolver cannot flatten them. *Fix:* restructure each component as an object (`background`, `foreground`, `radius`, `minHeight`, …) and move the narrative rationale to the Components body section, which already exists.
- **medium** Contrast targets are effectively absent from DESIGN.md. EXPERIENCE.md's Accessibility Floor says "Visual contrast ratios live in DESIGN.md" but DESIGN.md states none; the single ratio in the pair (7.1:1) lives in EXPERIENCE.md. Load-bearing unstated combinations: `gold` on `green-800` (winner name; computes to ≈4.3:1 — passes AA large-text only) and `ink-on-dark-muted` on `green-800` (progress labels; ≈4.4:1) (DESIGN.md Colors / winner-card / split-hero). *Fix:* add a short contrast table to DESIGN.md Colors covering ink-on-dark/green-800, gold/green-800, ink-on-dark-muted/green-800, text-primary/surface-base, host-text/host-surface, with the AA threshold each must satisfy.
- **low** `ink-on-dark-muted: 'rgba(255,255,255,0.70)'` violates the spec's hex-string rule for colors (DESIGN.md frontmatter). *Fix:* use 8-digit hex `'#FFFFFFB3'` or define the flattened composite over green-800.
- **low** Orphan tokens never referenced anywhere: `green-100`, `border-mid`, `text-disabled`, `host-surface-raised`; `green-100` (#D1FAE5) duplicates `border-light`'s value, and `surface-base` duplicates `green-50` with both names used in different components (DESIGN.md frontmatter). *Fix:* delete unused tokens or state where they apply; pick one name per value where aliases aren't intentional.
- **low** `rounded` uses `pill` where the spec's conventional name is `full` (DESIGN.md frontmatter; design-md-spec.md). Internally consistent. *Fix:* optional rename to `full`, or leave and accept the convention delta.

- **low** `host-stat-pill` and `host-primary-action` are never referenced by name in EXPERIENCE.md; their behavior (live count updates; one-primary-CTA rule) is present but attached to the control-panel table, not the component names (EXPERIENCE.md Host control panel). *Fix:* add `{components.host-stat-pill}` / `{components.host-primary-action}` references at the relevant rows.
- **low** Question Bank "Package cards" and the "מהמאגר" badge have behavioral rules (EXPERIENCE.md Game builder & Question Bank, A13) but no visual spec in DESIGN.md components. ## 4. State coverage — adequate

Walked all three IA surfaces. The State Patterns matrix (game state × three surfaces) is a strong invention that earns its place — it covers lobby, question open, question closed, reveal, leaderboard, game over, participant-device offline, display disconnect, organizer disconnect, and late join. The conversation grammar guarantees no-silence across (state × message class). Empty states for builder and Question Bank are defined. Reduced-motion and reconnect states covered on the display.

### Findings
- **high** The Audience Display has no defined content for **Free-Text Questions** — neither the question stage (what replaces the `stage-option` rows: an answer hint? nothing?) nor the reveal stage (what replaces the per-option `distribution-bar`; where the correct answer text appears) (EXPERIENCE.md IA "Audience Display — stages" and Component Patterns "Audience Display stages" are MCQ-only; DESIGN.md has no free-text stage component). `epics.md` explicitly waits on this: Story 4.3 "(or a free-text answer hint)", Story 4.4 `[OQ-7: distribution presentation for free-text]`. This is inside the OQ-7 mandate (FR-10 per-state content) and blocks Epic 4 story extraction for FT questions. *Fix:* define the FT question-stage body (e.g., instruction line "כתבו את התשובה בוואטסאפ" in Heading 800) and FT reveal content (correct-answer card + answered/correct counts, or explicit "no distribution for FT"), plus a DESIGN.md component entry.
- **medium** The conversation grammar has no column for a Game **before its lobby opens**: the JOIN Code exists from Game creation (`draft`), and early `JOIN <code>` (organizers share codes in advance) resolves to neither "valid during lobby" nor "invalid code" (EXPERIENCE.md WhatsApp conversation grammar; PRD FR-1 covers lobby only). `wa/inbound.go` will hit this branch at the first pilot event. *Fix:* add a draft/pre-lobby column — e.g., reply "הקוד נכון אבל המשחק עוד לא נפתח — נסו שוב כשמתחילים" or treat as Invalid code, but decide it.
- **medium** Winner-tie presentation is undefined: `winner-card` and the winner/final-results templates assume a single winner, while epics Stories 3.9/4.6 carry the assumption "all tied names included as winners" with no UX to render it (EXPERIENCE.md winner takeover + message templates; DESIGN.md `winner-card`). *Fix:* specify the tie variant for the winner-card (two/three names stacked, score once) and the tie wording for the final-results and winner messages.
- **low** The grammar column "Question closed / Reveal" doesn't explicitly include the `leaderboard` state (the state machine has six states; the table names four columns) — behavior is inferable but not stated (EXPERIENCE.md grammar table vs. architecture's state enum). *Fix:* rename the column "Between questions (closed / revealed / leaderboard)".
- **low** The `שם:` row returns "Name updated" in every column with no registered/unregistered distinction — an unregistered sender has no name to update (EXPERIENCE.md grammar table). *Fix:* footnote: unregistered `שם:` → Help.
- **low** Host dashboard sign-in error states and cold-load treatment are not specified beyond the generic error principles (EXPERIENCE.md Host Dashboard IA). Epics Story 1.2 covers sign-in via UX-DR12; acceptable for a pilot desktop tool. *Fix:* optional one row in State Patterns.
